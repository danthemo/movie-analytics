# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
на разработку программы «Разработка интеллектуальной веб-платформы для формирования рейтинговых описаний фильмов на основе анализа эмоциональной тональности контента комментариев зрителей»

## 1. ВВЕДЕНИЕ
**Наименование программы:** Разработка интеллектуальной веб-платформы для формирования рейтинговых описаний фильмов на основе анализа эмоциональной тональности контента комментариев зрителей.

**Краткая характеристика области применения:**
Программа предназначена для автоматизации процесса поиска информации о кинофильмах, сбора пользовательских рецензий с открытых источников (Okko.tv), проведения семантического анализа текста и генерации сводного рейтинга.

## 2. ОСНОВАНИЕ ДЛЯ РАЗРАБОТКИ
Разработка осуществляется на основании семестрового задания.

**Утверждающая организация:** РТУ МИРЭА.

**Тема разработки:** movie-analytics-platform.

## 3. НАЗНАЧЕНИЕ РАЗРАБОТКИ
**Функциональное назначение:**
Автоматизация сбора (парсинга) отзывов, хранение информации о фильмах в реляционной базе данных, генерация краткой выжимки и оценки настроений (sentiment analysis) с помощью LLM.

**Эксплуатационное назначение:**
Использование конечными пользователями для быстрого получения оценки кинофильмов без необходимости изучения десятков отдельных рецензий.

## 4. ТРЕБОВАНИЯ К ПРОГРАММНОМУ ИЗДЕЛИЮ

### 4.1. Требования к функциональным характеристикам
1.  **Поиск и сбор данных:**
    *   Поиск фильмов по названию через веб-интерфейс.
    *   Автоматический парсинг метаданных фильма (год, постер, описание) и отзывов с платформы Okko.tv.
2.  **Анализ данных (AI):**
    *   Интеграция с Perplexity API для обработки текста отзывов.
    *   Генерация краткой выжимки (summary) на основе множества отзывов.
    *   Вычисление агрегированного рейтинга (1–10) на основе тональности текстов.
3.  **Хранение и управление:**
    *   Отображение списка фильмов с возможностью просмотра деталей и удаления записей.
4.  **Пользовательский интерфейс:**
    *   Веб-интерфейс для взаимодействия с системой (поиск, просмотр списка, детализация).

### 4.2. Требования к надёжности
*   Корректная обработка отсутствия данных или сбоев API внешних сервисов.
*   Целостность данных при каскадном удалении фильмов и связанных комментариев.

### 4.3. Условия эксплуатации
*   **Тип архитектуры:** Микросервисная (Go Backend + Python сервис).
*   **Среда развертывания:** Docker-контейнеры (для БД) и локальный запуск сервисов.
*   **Обслуживание:** Администратор системы с навыками работы с Docker, Go и Python.

### 4.4. Требования к составу и параметрам технических средств
*   **ОС:** Windows 10/11, Linux или macOS.
*   **ОЗУ:** не менее 4 ГБ (рекомендуется 8 ГБ для работы headless-браузера).
*   **Свободное место на диске:** 1 ГБ.
*   **ПО:** Go 1.21+, Python 3.10+, PostgreSQL 16, Docker Desktop.

### 4.5. Требования к информационной и программной совместимости
*   **Входные данные:** HTTP-запросы (REST API), JSON.
*   **Внутреннее взаимодействие:** HTTP-протокол между Go-сервисом (порт 8080) и Python-сервисом (порт 8000).
*   **Стек технологий:**
    *   **Backend:** Go (Clean Architecture: Handler-Service-Repository).
    *   **Scraper:** Python (FastAPI, Playwright).
    *   **Database:** PostgreSQL (GORM ORM).
    *   **Frontend:** JavaScript, HTML, CSS.
    *   **AI:** Perplexity API.

### 4.6. Требования к маркировке и упаковке
Не предусмотрены (веб-приложение распространяется через репозиторий кода).

### 4.7. Требования к транспортированию и хранению
Хранение исходного кода осуществляется в системе контроля версий (Git).

### 4.8. Специальные требования
*   Архитектура должна следовать принципам Clean Architecture.
*   Разделение ответственности между микросервисами.

## 5. ТРЕБОВАНИЯ К ПРОГРАММНОЙ ДОКУМЕНТАЦИИ

1.  Техническое задание (данный документ).

*   **Преимущества:** Использование LLM позволяет выявлять скрытый контекст и эмоциональную окраску.

# ОПИСАНИЕ ПРОГРАММЫ И ЗАПУСК

## 1. Общие сведения
**Обозначение:** Movie Analytics Platform
**Языки программирования:** Go, Python, JavaScript, SQL.

## 2. Структура проекта

```
C:.
├───cmd/server/ # Точка входа Go сервера
├───frontend/ # Статические файлы (HTML/CSS/JS)
├───internal/ # Внутренняя логика (Clean Architecture)
│ ├───api/handlers/ # HTTP обработчики
│ ├───db/ # Подключение к БД
│ ├───models/ # Структуры данных (GORM)
│ ├───repository/ # Работа с БД
│ ├───service/ # Бизнес-логика
│ └───pythonclient/ # Клиент для связи с Python-сервисом
│ └───pythonParser/# Микросервис на Python (FastAPI + Playwright)
└───pkg/ # Общие пакеты (Config, Logger)
```

## 3. Инструкция по запуску

### Предварительные требования
*   Установлены Go и Python.
*   Установлен Docker (для БД).
*   Получен API ключ Perplexity.

### Шаг 1: Настройка окружения
Создайте файл `.env` в корне проекта:

```
DATABASE_URL=postgres://postgres:password@localhost:5432/moviedb?sslmode=disable
PORT=8080
PERPLEXITY_API_KEY=api_key
```

### Шаг 2: Запуск Базы Данных

```
docker run --name movie-db -e POSTGRES_PASSWORD=password -e POSTGRES_DB=moviedb -p 5432:5432 -d postgres
```

### Шаг 3: Запуск Python Microservice

```
cd internal/pythonclient/pythonParser
python3 -m venv venv
/venv/Scripts/activate
pip install -r requirements.txt
playwright install chromium
uvicorn service:app --host 0.0.0.0 --port 8000
```

### Шаг 4: Запуск Go Backend
Откройте новый терминал в корне проекта:

```
go mod tidy
go run cmd/server/main.go
```

### Шаг 5: Использование
Откройте браузер и перейдите по адресу: `http://localhost:5500` (или путь к вашему index.html, если он раздается отдельно).
